Workshop: JavaScript Aufgaben – Listen and Rule

HTML5, drei Schichten

Eine Webseite besteht aus drei Sprachen, die verschiedene Aufgaben haben:

Sprache Bild Aufgabe
HTML Bricks Die Bausteine: Was gibt es auf der Seite? Titel, Absätze, Buttons.
CSS Paint Die Gestaltung: Wie sieht es aus? Schrift, Farbe, Layout, Animation.
JavaScript Interact + Rule Das Verhalten: Was passiert, wenn jemand etwas tut? Und was verändert sich dann?

Zwei Richtungen

1 · Interact: Die Seite hört zu

Alles, was User tun, ist für den Browser ein Event: ein Klick, ein Scrollen, ein Fahren mit der Maus über ein Element. Damit JavaScript davon erfährt, braucht es einen Listener, der zuhört. Wir schreiben ihn direkt als Attribut ins HTML:

<button onclick="antworten()">Call</button>

Das heisst: Wenn auf diesen Button geklickt wird, führe die Funktion antworten() aus.

Attribut Wann es reagiert
onclick Klick mit der Maus oder Tippen mit dem Finger
onmouseover / onmouseout Die Maus fährt über ein Element bzw. verlässt es (das «hover»). Auf Touch-Geräten nicht verlässlich.
onfocus Ein Element wird ausgewählt, z. B. mit der Tab-Taste oder durch Klick in ein Eingabefeld
onscroll Es wird gescrollt, z. B. <body onscroll="…">

2. Das DOM: die Bühne dazwischen

Eure index.html ist zunächst nur Text in einer Datei. Wenn der Browser sie öffnet, liest er diesen Text und baut daraus ein Modell im Speicher: das DOM (Document Object Model).

Das DOM ist wie ein Baum aufgebaut. Jedes Element ist ein Knoten (Node), verschachtelte Elemente hängen als Äste darunter:

<body>                         body
  <h1>Call</h1>                 ├── h1
  <p>Ein Satz wartet</p>        ├── p
  <button>weiter</button>       └── button
</body>

JavaScript arbeitet nie direkt mit eurer Datei, sondern immer mit diesem Baum. Darum ist das DOM die Verbindungsschicht: Beide Richtungen aus der Skizze laufen hier durch.

  • Zuhören: Die Listener hängen an den Knoten. Klickt jemand auf den Button, meldet der Button-Knoten das Event an JavaScript.
  • Regieren: JavaScript sucht sich einen Knoten und verändert ihn. Der Browser zeichnet die Seite sofort neu.

3 · Rule: JavaScript regiert die Seite

JavaScript kann jeden Knoten im DOM finden und verändern. Damit hat es Zugriff auf beide anderen Schichten:

  • Auf die Bricks: Text ändern, neue Elemente anhängen, Elemente klonen oder entfernen.
  • Auf die Paint: Jede CSS-Eigenschaft eines Elements setzen.
Stellt euch die Seite wie eine Bühne vor. HTML sind die Requisiten und Darstellenden, CSS ist Kostüm und Licht. JavaScript ist die Regie: Sie wartet auf ein Stichwort aus dem Publikum (Event) und gibt dann Anweisungen, wer auftritt, wer die Farbe wechselt, wer antwortet.

Exkurs: Fingerprint

Die Regie sieht mehr, als man denkt. JavaScript kann den Browser vieles über sich selbst fragen: Bildschirmgrösse, Sprache, Zeitzone, Betriebssystem, Grafikkarte, sogar welche Schriften installiert sind. Einzeln ist das harmlos. Zusammen ergibt es oft eine Kombination, die nur ein einziger Browser auf der Welt hat: einen Fingerprint. Damit lassen sich Menschen über Websites hinweg wiedererkennen, auch ohne Cookies.

Schritt für Schritt

Wir bauen zusammen ein kleines Beispiel auf. Ihr könnt mitschreiben oder zuschauen und später hier nachlesen.

  2. Funktionetwas tun

  4. StylePaint verändern

1 · JavaScript einbinden

Legt neben der index.html eine Datei script.js an und verknüpft sie ganz unten im <body>:

index.html 
<body>

  <h1 id="titel">Call</h1>

  <script src="script.js"></script>
</body>
Warum ganz unten? Der Browser liest die Seite von oben nach unten. Steht das Script am Schluss, sind alle Bausteine schon da, wenn die Regie zu arbeiten beginnt.

2 · Eine Funktion, die etwas tut

Eine Funktion ist wie ein Rezept: Sie wird einmal aufgeschrieben, aber erst ausgeführt, wenn jemand sie aufruft.

script.js 
function antworten() {
  alert("Response!");
}

Speichern, Seite neu laden: Es passiert noch nichts. Die Funktion wartet.

3 · Ein Button ruft die Funktion auf

index.html 
<button onclick="antworten()">Call</button>

Jetzt erscheint beim Klick ein Fenster. Das onclick ist der Listener, die Klammern () bedeuten: Funktion jetzt ausführen.

4 · DOM-Manipulation: Style setzen

Statt eines Fensters soll sich die Seite selbst verändern. Mit document.getElementById() findet JavaScript ein Element über seine id:

script.js 
function antworten() {
  const titel = document.getElementById("titel");

  titel.textContent = "Response";
  titel.style.color = "red";
  titel.style.fontSize = "120px";
  titel.style.letterSpacing = "0.2em";
}

CSS-Eigenschaften mit Bindestrich schreibt man in JavaScript zusammen, das nächste Wort beginnt gross:

CSS JavaScript
font-size style.fontSize
background-color style.backgroundColor
letter-spacing style.letterSpacing
font-family style.fontFamily

5 · DOM-Manipulation: Nodes anhängen und klonen

JavaScript kann auch neue Bausteine auf die Bühne holen. Entweder ein ganz neues Element erzeugen oder ein bestehendes kopieren:

script.js 
// Ein neues Element erzeugen und anhängen
function neueZeile() {
  const zeile = document.createElement("p");
  zeile.textContent = "Und noch eine Antwort";
  document.body.appendChild(zeile);
}
index.html 
<button onclick="neueZeile()">Mehr</button>

Bei jedem Klick wächst die Seite. cloneNode(true) kopiert das Element mit allem, was darin steht.

Die Konsole ist euer Kontrollraum. Rechtsklick auf die Seite → Untersuchen → Tab Konsole. Dort erscheinen Fehlermeldungen in Rot. Mit console.log("bin hier"); in einer Funktion seht ihr, ob sie überhaupt aufgerufen wird.

Übung Interaktion: Ein Satz wartet, ein Button ist kitzlig

In eurer CSS-Animation lief der Dialog von selbst ab, das Timing war festgelegt. Jetzt gebt ihr einen Teil des Timings aus der Hand: Ein Satz erscheint und wartet. Ein Button atmet, er lädt ein. Erst wenn die User antworten, geht es weiter.

Ihr könnt mit eurem Liedtext aus der letzten Übung weiterarbeiten. Fragt euch:

  • Wer ist der Call, wer die Response? Ist der User eine Stimme im Dialog oder das Publikum?
  • Wie wartet etwas? Ungeduldig, ruhig, kaum sichtbar?
  • Was trägt der Button: ein Wort, eine Frage, nur eine Form?
  • Was passiert nach dem Klick: Erscheint etwas, verändert sich etwas, wächst etwas?

Boilerplate

Drei Dateien in einem Ordner. Bewusst ohne Gestaltung: Das ist eure Aufgabe.

index.html 
<!DOCTYPE html>
<html lang="de">
<head>
  <meta charset="UTF-8">
  <title>Ein Satz wartet</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>

  <p id="zeile1">HI Dear</p>
  <p id="wartet">Oh, you're tickling me!</p>
 

  <button id="knopf" onclick="weiter()">I long for your click</button>

  <script src="script.js"></script>
</body>
</html>
style.css 
/* Zeilen, die noch warten, sind versteckt */
#wartet {
  display: none;
}

/* Der Button atmet */
#knopf {
  animation: atmen 3s ease-in-out infinite;
}

@keyframes atmen {
  0%, 100% { transform: scale(1); }
  50%      { transform: scale(1.1); }
}
script.js 
// Die Antwort finden und zeigen


function weiter() {
  
  const zeile = document.getElementById("wartet" );
  zeile.style.display = "block";


}

Ideen zum Weiterbauen

  • Der Button ändert bei jedem Klick seine Message: knopf.textContent = "und dann?";
  • Die Animation des Knopfs stoppt animation-play-state: paused
  • Die Antwort kommt nicht sofort: eine CSS-Animation mit animation-delay auf den Zeilen.
  • Ein anderer Listener: onmouseover statt onclick. Was ändert sich am Dialog? (Und was passiert auf dem Handy?)

Wenn etwas nicht funktioniert

Problem Häufige Ursache
Beim Klick passiert gar nichts Die script.js ist nicht verknüpft oder der Dateiname stimmt nicht. In der Konsole nachschauen.
Konsole meldet … is not defined Der Funktionsname im onclick ist anders geschrieben als in der script.js. Gross- und Kleinschreibung zählen.
Konsole meldet Cannot read properties of null JavaScript findet das Element nicht: Die id im HTML stimmt nicht mit der im getElementById() überein.
Die Funktion läuft nicht beim Klick Im onclick fehlen die Klammern: weiter(), nicht weiter.
Der Style wird nicht übernommen Die Eigenschaft ist mit Bindestrich geschrieben (font-size statt fontSize) oder die Einheit fehlt ("120px", nicht 120).
Änderungen erscheinen nicht Datei nicht gespeichert oder Seite nicht neu geladen.
