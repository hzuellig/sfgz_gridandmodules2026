Übung: Deine gefundene Liste

Du kennst jetzt Tags, Selektoren (Tag, Klasse, ID), das Box Model, Fonts, Masseinheiten und Pfade. Diese Übung braucht kein Layout – nur eine Liste, die du typografisch gestaltest.

Kurz zur Erinnerung: Du hast vorhin eine bestehende Liste recherchiert und gefunden – nicht selbst erfunden. Eine Liste, die entweder ordnet (z. B. Farbnamen, Fachbegriffe), erzählt (z. B. Produktnamen, ein Milieu) oder poetisch ist (spielt mit Sprache, Bild, Klang) – ausgewählt danach, was dich am meisten anspricht. Genau diese Liste ist jetzt die Grundlage für die Übung.

Teil 1: HTML – die Liste

Zwei Bausteine reichen: <ul> für eine ungeordnete Liste, <li> für jeden Eintrag.

<h1>Poetische Namen für Wolken</h1>
<ul>
  <li>Himmelswatte</li>
  <li>Nachtflüsterer</li>
  <li>Sternenschleier</li>
  <li>Traumgebirge</li>
</ul>

Das bleibt so – daran ändert sich für den Rest der Übung nichts mehr. Alles Weitere passiert im CSS.

Teil 2: CSS – Typografie

Standardmässig sieht eine Liste aus wie eine Liste: Punkte davor, Einrückung, Browser-Standardschrift. Das änderst du zuerst:

ul {
  list-style: none;
  padding: 0;
}

Jetzt ist die Liste ein leeres Blatt – und genau hier beginnt die eigentliche Arbeit. Eine gute typografische Liste steht und fällt mit vier Eigenschaften:

Eigenschaft Was sie steuert Faustregel
font-family Charakter der Schrift Eine bewusste Wahl, kein Zufall – Serif wirkt anders als Sans oder Mono
font-size Lesbarkeit, Gewicht auf der Seite 16–19px bzw. entsprechend in rem, eher nicht kleiner
line-height (Zeilendurchschuss) Luft zwischen den Zeilen innerhalb eines Eintrags 1.4–1.6 – zu eng wirkt gequetscht, zu weit zerfällt der Text
letter-spacing Abstand zwischen Buchstaben Meist bei 0 lassen; nur für Kleingedrucktes/Nummern leicht spreizen
Zeilendurchschuss ≠ Abstand zwischen den Einträgen: line-height wirkt innerhalb eines <li> (falls der Text umbricht), padding/margin auf dem <li> wirkt zwischen den Einträgen. Meist macht der Abstand zwischen den Einträgen (padding) den grösseren optischen Unterschied – nicht der Zeilendurchschuss selbst.

Beispiel: eine typografisch durchdachte Liste

So könnte das Prinzip aussehen – eine Liste mit Nummerierung, Trennlinien und etwas Luft:

  • 01 Himmelswatte
  • 02 Nachtflüsterer
  • 03 Sternenschleier
  • 04 Traumgebirge
<ul class="archiv">
  <li><span class="nr">01</span> Himmelswatte</li>
  <li><span class="nr">02</span> Nachtflüsterer</li>
</ul>
.archiv {
  list-style: none;
  padding: 0;
  border-top: 1px solid #ddd;
}

.archiv li {
  
  padding: 14px 4px;
  border-bottom: 1px solid #ddd;
  font-family: Georgia, serif;
  font-size: 1.5rem;
  line-height: 1.1;
}

.nr {
  font-family: monospace;
  font-size: 12px;
  color: #999;
}

:hover – Reaktion auf die Maus

:hover ist eine Pseudoklasse: kein eigenes HTML-Element, sondern ein zusätzlicher Zustand, den ein Element annehmen kann – nämlich genau dann, wenn sich der Mauszeiger gerade über ihm befindet. Sobald die Maus wieder wegbewegt wird, verschwindet der Effekt automatisch wieder.

Die Syntax: Selektor, Doppelpunkt, hover.

li:hover {
  color: #1be07d;
}

Das bedeutet: alle li-Elemente bekommen diese Farbe, aber jeweils nur so lange, wie die Maus über dem einzelnen Element steht. Du brauchst dafür kein zusätzliches HTML, keine Klasse, kein JavaScript – nur diese eine CSS-Regel.

Der Effekt kann dezent sein – nur die Textfarbe ändert sich:

  • 01 Himmelswatte
  • 02 Nachtflüsterer
.archiv li:hover {
  color: #1be07d;
}

...oder auffällig – z. B. wenn Hintergrund und Text komplett wechseln:

  • Himmelswatte
  • Nachtflüsterer
.archiv li:hover {
  background: black;
  color: white;
}
Wichtig: Ob dezent oder auffällig ist eine gestalterische Entscheidung – sie sollte zum Charakter deiner Liste passen. Eine ruhige, poetische Liste verträgt oft einen leisen Hover (Farbwechsel), eine plakative Liste darf auch einen lauten Hover haben (Farbumkehr, Grössenwechsel, Unterstreichung). Wichtig ist nur: jede Liste braucht mindestens einen :hover-Effekt – das gehört zur Aufgabe unten.

Teil 3: Referenzen aus der Grafik

Die 2000er waren in der Grafik die Hochzeit von „programmatischen" Listen und Indexen in der Gestaltung – vor allem im niederländischen und Schweizer Design, wo Systematik selbst zum ästhetischen Statement wurde. Ein paar Beispiele:

  • Lineto
  • Studio Norm
  • Experimental Jetset
  • Stoos Architekten
  • Pattern Index
  • Joost Grootens
Schau dir diese Beispiele an: es sind simple, vertikale Listen von Einträgen, ohne Bilder, ohne Layout-Schnickschnack. Was sie gut macht, ist reine Typografie: Schriftwahl, Schriftgrösse, Zeilenabstand, feine Trennlinien, vielleicht dezente Nummerierung, im Web ein :hover-Effekt – genau das, was du jetzt selbst umsetzt.

Deine Aufgabe

Nimm deine gefundene Liste – dasselbe HTML schreibst du nur einmal. Dann gestaltest du sie dreimal komplett unterschiedlich, ausschliesslich mit CSS.

  1. HTML schreiben – eine Überschrift + eine <ul> mit deinen gefundenen Einträgen. Dieses HTML bleibt für alle drei Entwürfe identisch.
  2. Datei dreimal kopieren – drei identische HTML-Dateien mit demselben Inhalt.
  3. Entwurf 1 – eine Schrift, Grösse und Zeilenabstand wählen, die zum Charakter deiner Liste passt (poetisch, sachlich, verspielt ...).
  4. Entwurf 2 – bewusst etwas anderes: andere Schriftart-Kategorie (z. B. Serif statt Sans), anderer Rhythmus, andere Art der Trennung zwischen den Einträgen.
  5. Entwurf 3 – nochmals eine ganz andere Richtung. Wenn Entwurf 1 ruhig war, darf Entwurf 3 laut sein, oder umgekehrt.
  6. Hover-Effekt – in jedem der drei Entwürfe, aber jeweils passend zum Charakter des Entwurfs (siehe Teil 2).

Checkliste

  • Drei Dateien mit identischem HTML – nur das CSS unterscheidet sich
  • Liste ist eine <ul>/<li>-Struktur, keine Tabelle, kein Menü
  • Die drei Entwürfe unterscheiden sich in Schriftcharakter, Rhythmus und Art der Trennung – nicht nur in der Farbe
  • font-size und line-height in jedem Entwurf explizit gesetzt und begründbar
  • Abstand zwischen den Einträgen mit padding/margin/border-bottom
  • Mindestens ein :hover-Effekt pro Entwurf
Bonusfrage zum Nachdenken: Schau dir auf stoosarchitekten.ch/projekte die Zeilenhöhe der Tabelle an: Sie wirkt kompakt, aber nicht eng. Miss testweise an deiner eigenen Liste – wie viel padding und line-height braucht es, damit dichte Information trotzdem atmet?
