Git, GitHub & GitHub Pages

Bis jetzt liegen eure Seiten nur auf eurem Rechner. Heute bringt ihr sie ins Netz: mit einer Startseite, die alle eure Übungen verlinkt, und einer eigenen Adresse, die ihr teilen könnt.

Teil 1: Was ist Git?

Git ist ein Werkzeug zur Versionskontrolle. Es merkt sich, wie ein Projekt zu welchem Zeitpunkt aussah, wer was geändert hat und warum. Entwickelt wurde es 2005 von den Entwicklern des Linux-Betriebssystems, heute ist es der Standard, mit dem fast alle Software entwickelt wird.

Stellt euch Git wie das Inventarbuch eines Museums vor. Jedes Mal, wenn eine Ausstellung umgehängt wird, gibt es einen Eintrag: Datum, wer es war, was sich geändert hat. So kann man jederzeit nachschauen, wie die Wände vor drei Monaten aussahen – und im Notfall genau diesen Zustand wiederherstellen.

Ein solcher Eintrag heisst bei Git Commit. Die Abfolge aller Commits ist die Geschichte eures Projekts:

  • a3f9c21Startseite angelegt Mo, 10:14 · ihr
  • 7be04d8Flexbox-Übung hinzugefügt Mo, 11:02 · ihr
  • e51a9f3Galerie: Zoom-Tempo angepasst Di, 15:40 · ihr

Git ist kein Speicherplatz im Netz, sondern ein Programm, das auf dem eigenen Rechner läuft. Jede Kopie eines Projekts enthält die komplette Geschichte. Damit mehrere Leute zusammenarbeiten können, legt man aber meistens eine gemeinsame Kopie auf einen Server – und da kommt GitHub ins Spiel.

Die wichtigsten Begriffe

Begriff Bedeutung
Repository (Repo) Ein Projektordner, dessen Geschichte Git verwaltet
Commit Ein gespeicherter Zustand, mit kurzer Nachricht, was sich geändert hat
Commit Message Die Nachricht dazu, z. B. „Galerie-Bilder ausgetauscht“
Branch Ein Seitenzweig, um etwas auszuprobieren, ohne das Hauptprojekt anzutasten
main Der Hauptzweig – die „offizielle“ Version eures Projekts
Push / Pull Änderungen auf den Server hochladen / vom Server holen

Zum Nachschauen: Daniel Shiffmans Einführung zu Git und GitHub (Video, Englisch).

Teil 2: GitHub und GitHub Pages

GitHub ist eine Plattform, auf der Git-Repositories online liegen. Man kann dort Code speichern, teilen, gemeinsam daran arbeiten, Fehler melden und Projekte dokumentieren. GitHub gehört seit 2018 zu Microsoft. Eine Alternative ist GitLab.

GitHub Pages ist ein Dienst von GitHub, der aus einem Repository eine öffentliche Website macht – gratis, ohne eigenen Server. Ideal für statische Seiten aus HTML, CSS und Bildern, also genau das, was ihr baut.

Heute ohne Installation: Normalerweise arbeitet man mit Git auf dem eigenen Rechner und schickt die Änderungen dann zu GitHub. Heute machen wir alles direkt im Browser. Auch dabei entsteht bei jedem Upload ein Commit – ihr seht also trotzdem, wie Git funktioniert.

Teil 3: Projekt vorbereiten

Die Ordnerstruktur

Legt einen Projektordner an, in dem alle eure Übungen als Unterordner liegen. Ganz oben liegt eine index.html – eure Startseite.

mein-portfolio/
├── index.html              ← Startseite mit Links
├── flexbox-uebung/
│   ├── index.html
│   └── css/
├── zoom-galerie/
│   ├── index.html
│   ├── css/
│   └── images/
└── schriften/
    └── index.html

Warum heisst die Startseite index.html? Ein Webserver zeigt automatisch die Datei mit diesem Namen an, wenn jemand einen Ordner aufruft. Ohne index.html findet GitHub Pages eure Seite nicht.

Die Startseite

Die Startseite verlinkt alle Übungen – mit den relativen Pfaden, die ihr schon kennt:

<!DOCTYPE html>
<html lang="de">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Mein Portfolio</title>
</head>
<body>
  <h1>Mein Portfolio</h1>
  <ul>
    <li><a href="flexbox-uebung/index.html">Flexbox-Übung</a></li>
    <li><a href="zoom-galerie/index.html">Zoom-Galerie</a></li>
    <li><a href="schriften/index.html">Schriften</a></li>
  </ul>
</body>
</html>

Die Startseite darf natürlich auch gestaltet sein – ihr wisst ja jetzt, wie man Dinge anordnet.

Tipp: Schreibt in den Links immer den ganzen Pfad bis zur index.html aus, also zoom-galerie/index.html und nicht nur zoom-galerie/. Online funktioniert beides, aber lokal auf eurem Rechner nur die ausgeschriebene Variante.

Dateinamen: die Regeln fürs Netz

  • Keine Leerzeichen und keine Umlaute: zoom-galerie statt Zoom Galerie, uebung statt übung.
  • Alles klein schreiben. Euer Mac oder PC unterscheidet oft nicht zwischen Bild.JPG und bild.jpg – der Server von GitHub schon. Ein Bild, das lokal funktioniert, fehlt dann online.
  • Bindestrich statt Leerzeichen, wenn ein Name aus mehreren Wörtern besteht.

Bevor ihr hochladet: Öffnet eure Startseite lokal im Browser und klickt jeden Link durch. Was hier nicht funktioniert, funktioniert online auch nicht.

Teil 4: Account anlegen

  1. Geht auf github.com und klickt auf Sign up.
  2. E-Mail-Adresse, Passwort und einen Benutzernamen eingeben.
  3. E-Mail bestätigen – GitHub schickt euch einen Code.
  4. Den Gratis-Plan wählen, falls GitHub danach fragt.
Benutzernamen gut überlegen: Er wird Teil eurer Webadresse, also benutzername.github.io. Wählt etwas, das ihr auch in einer Bewerbung verwenden würdet.

GitHub fordert euch unter Umständen auf, eine Zwei-Faktor-Authentifizierung einzurichten (z. B. mit einer Authenticator-App). Das ist normal und schützt euren Account.

Teil 5: Repository anlegen

  1. Oben rechts auf + klicken, dann New repository.
  2. Repository name: z. B. portfolio. Der Name wird Teil der Adresse, also auch hier: klein, ohne Leerzeichen.
  3. Public auswählen. Mit einem Gratis-Account funktioniert GitHub Pages nur mit öffentlichen Repositories.
  4. Auf Create repository klicken.
Öffentlich heisst öffentlich: Alles, was ihr hochladet, kann jede Person sehen – der Code und die Bilder. Ladet nur hoch, was ihr zeigen wollt und zeigen dürft (Achtung bei fremden Bildern und Schriften, siehe Lizenzen).

Teil 6: Dateien hochladen

  1. Im leeren Repository auf den Link uploading an existing file klicken. Später findet ihr das unter Add file → Upload files.
  2. Öffnet euren Projektordner, markiert den ganzen Inhalt (die index.html und alle Unterordner) und zieht ihn ins Browserfenster.
  3. Unten eine Commit Message schreiben, z. B. „Erste Version meines Portfolios“.
  4. Auf Commit changes klicken.
Häufigster Fehler: Zieht den Inhalt des Ordners ins Fenster, nicht den Ordner selbst. Sonst liegt eure index.html in einem Unterordner mein-portfolio/ – und die Startseite ist online nicht zu finden.

Schaut euch danach das Repository an: Liegt die index.html direkt auf der obersten Ebene? Sind alle Unterordner da? Und oben seht ihr euren ersten Commit – mit eurer Nachricht.

Teil 7: GitHub Pages einschalten

  1. Im Repository oben auf Settings klicken.
  2. Links in der Seitenleiste, im Bereich „Code and automation“, auf Pages.
  3. Unter „Build and deployment“ bei Source: Deploy from a branch.
  4. Bei Branch: main auswählen, daneben den Ordner / (root).
  5. Auf Save klicken.

Jetzt braucht GitHub ein bis zwei Minuten. Danach erscheint oben auf der Pages-Seite eure Adresse:

https://benutzername.github.io/portfolio/

Diese Adresse könnt ihr teilen, öffnen, auf dem Handy anschauen. Den Fortschritt seht ihr im Tab Actions: Ein grüner Haken heisst, die Seite ist online.

Teil 8: Änderungen hochladen

Ihr habt lokal etwas verbessert? Dann ladet die geänderten Dateien einfach nochmals über Add file → Upload files hoch. Dateien mit gleichem Namen am gleichen Ort werden ersetzt. Jeder Upload ist ein neuer Commit, und nach kurzer Zeit ist auch die Website aktualisiert.

Unter Commits (die Uhr mit der Zahl oben in der Dateiliste) seht ihr die ganze Geschichte eures Projekts – das Inventarbuch aus Teil 1.

Die Seite zeigt noch die alte Version? Das liegt oft am Browser-Cache. Neu laden mit Cmd + Shift + R (Mac) bzw. Strg + F5 (Windows).

Wenn etwas nicht funktioniert

Problem Häufige Ursache
404 – Seite nicht gefunden index.html liegt in einem Unterordner statt auf der obersten Ebene, oder heisst anders (z. B. Index.html)
Seite ohne Styling Pfad zur CSS-Datei stimmt nicht, oder Gross-/Kleinschreibung weicht ab
Bilder fehlen Gross-/Kleinschreibung (.JPG vs. .jpg), Leerzeichen im Namen, oder Bild wurde nicht mit hochgeladen
Links zu Übungen gehen nicht Ordnername im Link stimmt nicht mit dem echten Ordnernamen überein

Für heute

  1. Projektordner mit allen Übungen anlegen, Dateinamen prüfen.
  2. Startseite index.html bauen, die alle Übungen verlinkt. Lokal durchklicken.
  3. GitHub-Account und öffentliches Repository anlegen.
  4. Inhalt des Projektordners hochladen.
  5. GitHub Pages einschalten.
  6. Eure Adresse im Kurs-Chat teilen – und die Seiten der anderen anschauen.

Für später

Wenn ihr regelmässig an Projekten arbeitet, lohnt es sich, Git richtig auf dem eigenen Rechner einzurichten. Dann synchronisiert ihr direkt aus dem Code-Editor heraus, statt jedes Mal hochzuladen.
