Workshop: Begrüssungsszenen animieren

Eine Begrüssung ist nie einseitig. Jemand grüsst, jemand grüsst zurück, oder eben nicht. Heute entwickelt ihr eine kleine animierte Szene, die mit der Person rechnet, die eure Seite öffnet. Ihr arbeitet einzeln, testet aber zu zweit.

Teil 1: Die Begrüssung als Szene

Eine Begrüssung ist mehr als ein Wort. Sie ist eine kleine Szene: Die Seite grüsst, die Person, die sie öffnet, reagiert, und die Seite antwortet darauf. Und vielleicht sagt die Begrüssung mehr als nur «Hallo»:

«Hi.» … «Ich fühle mich heute müde.»
«Grüezi.» … «Sie sind spät.»
«Dear friend,» … «I have an urgent offer for you.»

Erst mit dem zweiten Satz entsteht ein Gegenüber mit einer Stimmung. Und die Stimmung gibt der Bewegung einen Grund: Ein müdes «Hallo» kommt langsam, sackt ab und braucht eine Pause, bevor der nächste Satz kommt.

Ruf und Antwort

Dialoge ohne Worte gibt es überall, wo Menschen gemeinsam etwas aufführen:

  • Call and Response in Gospel, Blues und Worksongs: Eine Stimme ruft, alle antworten. Die Antwort kann bestätigen, widersprechen oder etwas weiterführen.
  • Trading Fours im Jazz: Zwei Musiker:innen wechseln sich alle vier Takte ab und greifen auf, was die andere Person gerade gespielt hat.
  • Spiegelübung im Tanz und Theater: Eine Person führt, die andere folgt, bis man nicht mehr weiss, wer führt.
  • Kontaktimprovisation: Bewegung entsteht aus dem Kontakt, aus Gewicht geben und Gewicht nehmen.
  • Tango: Führen und Folgen als Gespräch, mit Einladungen, die man annehmen oder ablehnen kann.
  • Improvisationstheater: «Ja, und …»: Jedes Angebot wird angenommen und weitergeführt.

Für eure Szene heisst das: Was ist das Angebot eurer Begrüssung? Was passiert, wenn es angenommen wird? Und was, wenn nicht?

Wenn die Website zurückredet

Auch eine Website kann ein Gegenüber sein. Das Projekt click click click von Studio Moniker beobachtet, was ihr mit der Maus macht, und kommentiert es. Plötzlich merkt man: Jede Bewegung ist eine Antwort, auch das Nichtstun.

Mini-Dialoge schreiben (10 Minuten)

Schreibt zwei kurze Dialoge, höchstens zweimal hin und her, also vier Zeilen:

  • einen zwischen zwei Menschen, die sich über Technologie begegnen: Chat, SMS, Videocall, E-Mail …
  • einen zwischen Mensch und Technologie: Website, Sprachassistent, Fehlermeldung, Cookie-Banner …

Wer spricht zuerst? Welche Stimmung hat A, welche B? Lest euch die Dialoge zu zweit laut vor.

A: Ping. Bist du da?
B: Online. Seit Stunden schon.
A: Schön, dass sich unsere Bildschirme treffen.
B: Schön, dass du tippst.

Eure Dialoge sind das Rohmaterial für die Szene, die ihr später baut. Zuerst braucht ihr aber das Werkzeug, um Wörter in Bewegung zu bringen.

Teil 2: Was sind CSS-Animationen?

Transitions und Transforms kennt ihr schon. Eine Transition kennt nur Zustand A und Zustand B. Bei einer Animation könnt ihr beliebig viele Zustände dazwischen festlegen, sogenannte Keyframes.

Transition Animation
Zustände Zwei: vorher und nachher Beliebig viele Keyframes
Auslöser Eine Zustandsänderung, z. B. :hover Läuft von selbst, sobald die Seite lädt
Wiederholung Nein Beliebig oft, auch endlos
Eine Transition ist ein Schnitt mit Überblendung: Anfangsbild, Endbild, dazwischen rechnet der Browser. Eine Animation ist ein Daumenkino: Ihr zeichnet die wichtigen Seiten selbst, und der Browser füllt die Lücken dazwischen.

Animationen sichtbar machen

Teil 3: Die Syntax

Eine Animation besteht aus zwei Teilen: Zuerst wird sie mit @keyframes entworfen, dann wird sie einem Element zugewiesen.

/* 1. Animation entwerfen */
@keyframes hereinschieben {
  from {
    transform: translateX(0%);
  }
  to {
    transform: translateX(100%);
  }
}

/* 2. Animation zuweisen */
.wort {
  animation-name: hereinschieben;
  animation-duration: 3s;
}
  • Den Namen nach @keyframes wählt ihr frei. Mit diesem Namen wird die Animation zugewiesen.
  • from ist der Keyframe bei 0 %, to der bei 100 %.
  • Anders als bei transition müsst ihr nicht angeben, welche Eigenschaften animiert werden. Alles, was in den Keyframes steht, wird animiert.

Mehr als zwei Zustände: Prozente

@keyframes winken {
  0%   { transform: rotate(0deg);   color: black; }
  25%  { transform: rotate(-15deg); }
  50%  { transform: rotate(15deg);  color: red; }
  75%  { transform: rotate(-10deg); }
  100% { transform: rotate(0deg);   color: black; }
}

/* Keyframes mit gleichem Zustand lassen sich zusammenfassen */
@keyframes pulsieren {
  0%, 100% { opacity: 1; }
  50%      { opacity: 0.2; }
}

Teil 4: Die Animation steuern

Eigenschaft Was sie macht Beispiel
animation-duration Dauer eines Durchgangs 3s, 800ms
animation-delay Wartezeit vor dem Start 1s
animation-iteration-count Wie oft die Animation abgespielt wird, Standard ist 1 3, infinite (endlos)
animation-direction normal vorwärts, reverse rückwärts, alternate hin und her, alternate-reverse her und hin alternate
animation-timing-function Beschleunigung, wie transition-timing-function ease-in-out, linear, steps(5)
animation-fill-mode forwards behält den letzten Keyframe nach dem Ende, backwards zeigt den ersten schon während der Verzögerung, both beides both
animation-play-state Läuft oder ist angehalten. Angehalten und wieder gestartet, läuft sie dort weiter, wo sie stand. running, paused

Kurzform: animation

/* duration | timing-function | delay | iteration-count | direction | fill-mode | play-state | name */
animation: 3s ease-in 1s 2 reverse both paused hereinschieben;

/* meistens reicht viel weniger */
animation: hereinschieben 3s ease-in-out both;
Zwei Zeitangaben? Die Reihenfolge der Werte ist ziemlich frei. Bei den Zeiten aber gilt: Die erste ist immer die Dauer, die zweite die Verzögerung.

Teil 5: Buchstabe für Buchstabe

Typografische Animationen werden spannend, wenn sich nicht das ganze Wort bewegt, sondern jeder Buchstabe einzeln, leicht versetzt.

<h1 class="wort" aria-label="Hallo">
  <span aria-hidden="true" style="--i: 0">H</span>
  <span aria-hidden="true" style="--i: 1">a</span>
  <span aria-hidden="true" style="--i: 2">l</span>
  <span aria-hidden="true" style="--i: 3">l</span>
  <span aria-hidden="true" style="--i: 4">o</span>
</h1>
.wort span {
  display: inline-block; /* wichtig! */
  animation: huepfen 1.2s ease-in-out infinite alternate;
  animation-delay: calc(var(--i) * 0.12s);
}

@keyframes huepfen {
  0%   { transform: translateY(0) rotate(0deg); }
  60%  { transform: translateY(-24px) rotate(-6deg); }
  100% { transform: translateY(0) rotate(4deg); }
}
  • Mit aria-label liest ein Screenreader «Hallo» vor statt «H, a, l, l, o». Die einzelnen Buchstaben sind darum mit aria-hidden ausgeblendet.
  • Die Variable --i ist die Nummer des Buchstabens. calc(var(--i) * 0.12s) rechnet daraus für jeden Buchstaben eine eigene Verzögerung aus: 0s, 0.12s, 0.24s …
  • Ein span ist ein Inline-Element, und darauf wirkt transform nicht. Darum braucht es display: inline-block.

Teil 6: Animation und Interaktion

Eine Animation läuft von selbst. Das ist der Ruf, Zeile A eures Dialogs. Spannend wird es, wenn die Person antwortet, die die Seite öffnet. Ihre Antwort besteht nicht aus Worten, sondern aus Bewegungen der Maus. Mit CSS allein habt ihr dafür diesen Werkzeugkasten:

Verhalten in der Begegnung Im Browser CSS
sich nähern, Interesse zeigen Maus fährt über ein Element :hover
verweilen, länger hinschauen Maus bleibt liegen transition-delay, langsame Transition
berühren Maustaste gedrückt halten :active
antworten, sich einlassen anklicken, der Zustand bleibt bis zum nächsten Klick daneben :focus mit tabindex="0"
sich abwenden Maus verlässt das Element Transition zurück in den Grundzustand
ignorieren, nichts tun keine Interaktion animation-iteration-count, animation-fill-mode: Die Begrüssung gibt irgendwann auf

Beispiel

/* Die Antwort erscheint erst, wenn man verweilt */
.antwort {
  opacity: 0;
  transition: opacity 0.6s ease;
}

.hero:hover .antwort {
  opacity: 1;
  transition-delay: 1.5s; /* erst nach anderthalb Sekunden */
}
<section class="hero">
  <h1 class="wort" tabindex="0" aria-label="Hallo"> … </h1>
  <p class="antwort">Schön, dass du bleibst.</p>
</section>

Teil 7: Vom Dialog zur Szene

Jetzt wird aus eurem Mini-Dialog eine Szene. Zuerst auf Papier als Drehbuch, dann als Papierprototyp, den ihr zu zweit aufführt. Das geht schneller als Code, und ihr merkt sofort, ob eure Idee funktioniert.

Mini-Drehbuch und Papierprototyp

  1. Drehbuch schreiben (10 Minuten): Wählt einen eurer Mini-Dialoge. Die Seite spricht A, die Person antwortet als B, aber mit Hover, Klick, Verweilen oder Nichtstun statt mit Worten.
  2. Bauen (15 Minuten): Wort und Sätze aus Papier, dazu ein Rahmen als Viewport.
  3. Aufführen zu zweit (2 × 10 Minuten): Eine Person ist die Website, die andere die Besucherin.
  4. Auswerten und anpassen (5 Minuten): Drehbuch überarbeiten, Keyframes fotografieren.

1. Das Mini-Drehbuch

Das Drehbuch hat zwei Spalten: links, was die Seite von selbst macht, rechts, was sie tut, wenn die Person etwas tut. Bleibt sehr einfach. Und denkt auch an die leere Zeile: Was passiert, wenn niemand antwortet?

Zeit Die Seite von selbst Wenn die Person …
0 s Leerer Screen. Ein Buchstabe nach dem anderen sackt von oben ins Bild: «H a l l o».
3 s Das Wort gähnt: Es wird langsam breiter und wieder schmaler. … näher kommt (Hover): Das Wort schreckt auf, die Buchstaben stehen gerade.
5 s … verweilt: Klein darunter erscheint «Ich fühle mich heute müde.»

2. Bauen

  • Die Buchstaben eures Worts gross ausschneiden, auch den zweiten Satz, wenn ihr einen habt. Schichten in verschiedenen Farben sind erlaubt.
  • Einen Rahmen bauen: ein Karton mit einem ausgeschnittenen Fenster im Format eines Bildschirms. Das ist euer Viewport. Was ausserhalb liegt, ist unsichtbar, wie bei overflow: hidden.
  • Alles bereitlegen, was von aussen ins Bild kommen soll.

3. Aufführen zu zweit

Eine Person spielt die Website und bewegt die Papierbuchstaben im Rahmen, so wie es im Drehbuch steht. Die andere spielt die Besucherin und hat nur einen Finger als Mauszeiger.

  • Finger schwebt über dem Papier: Hover.
  • Finger tippt: Klick.
  • Finger zieht sich zurück: sich abwenden.
  • Hände im Schoss: nichts tun. Probiert auch das mindestens einmal aus!
Die Regeln: Die Besucherin kennt das Drehbuch nicht und verhält sich so, wie sie möchte. Die Website darf nichts erklären, sie reagiert nur. Und sie darf nur, was CSS auch kann: keine Buchstaben, die dem Finger folgen, nichts, was sich eine Seite merkt, wenn man sie wieder öffnet. Danach werden die Rollen getauscht.

4. Auswerten

Die Besucherin erzählt, die Website hört nur zu:

  • Welche Stimmung hast du gespürt? Steht sie im Drehbuch?
  • Hast du gemerkt, dass du antworten kannst? Woran?
  • Was hast du erwartet, und was ist passiert? Wo warst du überrascht oder irritiert?
  • Wolltest du bleiben, oder wolltest du weiterklicken?

Danach passt ihr euer Drehbuch an. Fotografiert die wichtigsten Momente eurer Papierszene. Das sind eure Keyframes.

Teil 8: Umsetzung beginnen

Legt euer Drehbuch und die Fotos neben den Bildschirm und arbeitet in dieser Reihenfolge:

  1. Stillstand: Zuerst die Szene ohne Bewegung: Schrift, Grösse, Farbe, Position. Welche Schrift passt zur Stimmung?
  2. Von selbst: Die Animation, die läuft, wenn niemand etwas tut.
  3. Reaktion: Eine Interaktion nach der anderen, die wichtigste zuerst.
  4. Feinschliff: Timing, Pausen, Verzögerungen. Hier entscheidet sich, ob die Stimmung ankommt.

Startvorlage

<section class="hero">
  <h1 class="wort" lang="it" tabindex="0" aria-label="Ciao">
    <span aria-hidden="true" style="--i: 0">C</span>
    <span aria-hidden="true" style="--i: 1">i</span>
    <span aria-hidden="true" style="--i: 2">a</span>
    <span aria-hidden="true" style="--i: 3">o</span>
  </h1>
  <p class="antwort" lang="de">Ich fühle mich heute grossartig.</p>
</section>
body {
  margin: 0;
}

.hero {
  height: 100vh;
  height: 100dvh;      /* berücksichtigt die Adressleiste auf dem Handy */
  display: grid;
  place-content: center;
  text-align: center;
  overflow: hidden;    /* nichts ragt über den Rand hinaus */
}

.wort {
  margin: 0;
  font-size: 25vw;     /* Schriftgrösse wächst mit der Fensterbreite */
  line-height: 1;
}

.wort:focus {
  outline: none;       /* nur wenn ihr den Fokus anders sichtbar macht! */
}

.wort span {
  display: inline-block;
  animation: auftauchen 1s ease-out both;
  animation-delay: calc(var(--i) * 0.15s);
}

@keyframes auftauchen {
  0%   { opacity: 0; transform: translateY(40%) scale(0.6); }
  70%  { opacity: 1; transform: translateY(-5%) scale(1.05); }
  100% { opacity: 1; transform: translateY(0) scale(1); }
}

.antwort {
  opacity: 0;
  transition: opacity 0.6s ease;
}

.hero:hover .antwort {
  opacity: 1;
  transition-delay: 1.5s;
}

@media (prefers-reduced-motion: reduce) {
  .wort span {
    animation: none;
  }
}
Viewport-Einheiten: vw ist ein Hundertstel der Fensterbreite, vh ein Hundertstel der Fensterhöhe. Damit skaliert die Schrift mit dem Bildschirm. Testet in einem breiten und einem schmalen Fenster, und auf dem Handy.
